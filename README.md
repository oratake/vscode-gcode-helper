# vscode-gcode-helper

マシニングセンタで用いる G-code を VSCode で編集する際に便利になる拡張機能です。

## 目的

マシニングセンタで用いる G-code を VSCode で編集しているが、編集の際に便利になるような VSCode 拡張機能を作りたい、という出发点のプロジェクトです。

## 現状ステータス

> **検討段階・開発未着手です。**
>
> この README の内容は「**方向性として検討しているもの**」であり、確定仕様ではありません。各機能の実装前に個別に調査・確定していきます。

## 使うソフトとの連携

- 基本は **Autodesk Fusion** 向けに特化する想定。
- 一般的な G-code にも当然対応できることを前提とする。
- G-code 方言は **FANUC 系**として扱う想定。

## 検討中の機能

以下は思いつきからの案です。後で個別に Issue を切って開発していく予定です。

### 1. 行コメントのフロート表示
シーケンス番号がある行のコメントをフロートで表示し続ける。
- 何行目から何行目までを表示しておく、という形がよさそう。

### 2. 工具情報の表示
Fusion から工具情報を取得し、サイドに表示しておく。
- **要調査**: 取得経路（Fusion Add-In vs. Fusion MCP を単純な API として利用）。
- 設計の方針: 取得経路とは独立に、工具情報の「成果物」を **JSON/YAML ファイル**で置き、VSCode 側がそれを読む。機構が後から変わっても読込側は無変更になる。

### 3. 最低 Z の把握
シーケンス内で最低の Z がどこか把握できるようにする。
- 刃物長と干渉のチェックのため。
- 例: N10 なら N20 手前行までの間に一番 Z が低い点を検索しておく。クリックでジャンプできるようにする。

### 4. モーダル管理（ISP 的な処理・やや重いタスク）
カーソルを置いた時点で、現在のモーダル状態を把握し表示する。
- 例: G90 / G54 だとか、工具径補正がかかっている / M66 で解除されている、など。
- モーダルルールは**設定駆動のルールテーブル**として持ち、`package.json` の設定から自社の環境に合わせて上書き可能にする想定。

## 開発の方向性（検討中・未確定）

- **技術スタック**: TypeScript + esbuild（VSCode 拡張の公式テンプレートに準ずる想定）。
- **構造**: 純粋ロジック（`core/`）と VSCode 依存層（`ui/`）を分離し、VSCode を起動せずに単体テストできるようにする。
- **Fusion 連携**: 独立したスロット（`integration/fusion/`）として置き、調査前に特定機構へコミットしない。

コーディング LLM 向けの指示は `AGENTS.md` を参照してください。
